# Changelog: July 8, 2026

## Fix Order Chasing strategy_id Propagation & Stale Orders

Addressed a concurrency issue where manually chasing (replacing) a working order (specifically `GAP_RECON`) led to duplicate trade confirmation modals, over-execution, and stale `PENDING` placeholders on the UI dashboard.

### **Highlights**
*   **Targeted Strategy Tracking (New ID Mapping)**: Modified `chase_order` in `execution.rs` to extract the new replacement order ID from the Schwab API response's `Location` header, returning a custom `ChaseResult` enum (`Replaced(new_id)`, `AlreadyAtTarget`, `NotFound`).
*   **Immediate Stub Propagation**: Updated the Axum REST handler (`api_chase_order` in `web.rs`) to immediately look up the old order's `strategy_id` and push a local stub order with the new order ID to the Supervisor's `working_orders` list.
*   **Duplicate Trade Modal Protection**: By maintaining the `GAP_RECON` strategy mapping on the replacement order, future gap reconciliation runs are correctly blocked from popping up duplicate confirmation modals while the replacement order is still working.
*   **Safety Cleanups**: Restructured API error paths to correctly distinguish between a successful replacement, an already-at-target order (requires no change/stub), and an order that was not found (e.g. already filled at exchange).
